# 🔄 Автоматическое переключение сетевого адаптера

## Дата: 20 октября 2025

---

## 📋 Описание

Реализовано **автоматическое переключение сетевого адаптера** при изменении локального IP во время активного мониторинга.

---

## 🎯 Как это работает

### Алгоритм работы (аналогично LocalIP):

```
1. TicksLoop вызывается каждую секунду
   ↓
2. Проверка активного процесса
   ↓
3. Определение LocalIP (каждые 30 сек для одного процесса)
   ↓
4. Если LocalIP изменился:
   ├─ Обновление App.meterState.LocalIP
   ├─ Синхронизация UI (textbox + ComboBox)
   └─ [НОВОЕ] Автоматическое переключение адаптера
       ↓
5. SwitchAdapterIfNeeded(newLocalIP):
   ├─ Проверка текущего адаптера
   ├─ Поиск нового адаптера по IP
   ├─ Остановка старых workers
   ├─ Запуск новых workers на новом адаптере
   └─ Сохранение состояния мониторинга
```

---

## ⚙️ Технические детали

### Метод: `SwitchAdapterIfNeeded(string newLocalIP)`

**Расположение:** `Forms\GUI.cs`

**Вызывается:** При изменении LocalIP во время активного мониторинга

**Логика:**

```csharp
1. Проверка необходимости переключения
   - Сравнение текущего IP адаптера с новым LocalIP
   - Если совпадают → выход (переключение не нужно)

2. Поиск нового адаптера
   - Перебор всех адаптеров
   - Поиск по IP адресу
   - Получение PacketDevice

3. Переключение в зависимости от режима:
   
   A) Мультиадаптерный режим (captureAll / vpnBypass):
      - Остановка всех текущих workers (_pcapWorkers)
      - Очистка _allSelectedAdapters
      - Пересоздание списка адаптеров с учетом VPN приоритетов
      - Запуск новых workers для всех адаптеров
   
   B) Одноадаптерный режим:
      - Остановка pcapWorker
      - Обновление selectedAdapter
      - Запуск нового worker на новом адаптере
```

---

## 🔄 Интеграция с LocalIP проверкой

| Этап | Действие | Частота |
|------|----------|---------|
| 1️⃣ **Проверка процесса** | AutoDetectMngr.GetActiveProcessName() | Каждую 1 сек |
| 2️⃣ **Проверка LocalIP** | LocalIPDetector.DetectLocalIPForActiveProcess() | Каждые 30 сек (тот же процесс) |
| 3️⃣ **Обновление UI** | local_ip_textbox + adapters_list ComboBox | При изменении IP |
| 4️⃣ **Переключение адаптера** | SwitchAdapterIfNeeded() | При изменении IP + активный мониторинг |

## 🔍 Режимы работы

### 1️⃣ Мультиадаптерный режим

**Активируется при:**
- `capture_all_adapters = True`
- `vpn_bypass_basic = True`
- `vpn_bypass_advanced = True`

**Поведение:**
- Перезапускаются ВСЕ workers (_pcapWorkers)
- Пересоздается список _allSelectedAdapters
- Учитываются VPN приоритеты

**Особенности:**
- Захват идет одновременно со всех адаптеров
- Встроенная дедупликация пакетов
- Автоматический выбор VPN адаптеров

### 2️⃣ Одноадаптерный режим

**Активируется при:**
- Все вышеуказанные опции = False

**Поведение:**
- Перезапускается один worker (pcapWorker)
- Обновляется selectedAdapter
- Обновляется lastSelectedAdapterID

**Особенности:**
- Захват только с одного адаптера
- Минимальная нагрузка на систему

## 🛡️ Защита и стабильность

### Анти-реэнтерабельность
```csharp
// В SwitchAdapterIfNeeded НЕТ блокировки
// Вызов защищен родительским контекстом (updateMetherStateFromActiveWindow)
// который выполняется в главном потоке UI
```

### Корректная остановка workers
```csharp
foreach (var worker in _pcapWorkers)
{
    if (worker != null && worker.IsBusy)
    {
        worker.CancelAsync(); // Мягкая остановка
    }
}
Thread.Sleep(100); // Задержка для завершения
```

### Проверка состояния
```csharp
if (!App.meterState.IsTracking) return; // Не переключать если мониторинг не активен
if (currentAdapterIP == newLocalIP) return; // Избегать лишних переключений
```

## ⚠️ Известные ограничения

1. **Кратковременная потеря пакетов** (~100-200 мс) во время переключения
2. **Не работает если мониторинг не запущен** (требуется IsTracking = true)
3. **Зависит от корректности LocalIPDetector** (если IP определен неверно, переключение не произойдет)
