# План внедрения драйвера для обнаружения VPN-трафика

## Цели
- Получать PID и имя процесса до того, как VPN-клиент зашифрует трафик.
- Объединить источники данных (SharpPcap, IpHlpApi/ETW, WFP) в единый кэш сопоставлений.
- Сохранить совместимость: при отсутствии драйвера приложение работает с ограниченным функционалом.

## Предпосылки и требования
- Windows 10/11 x64.
- Visual Studio 2022 + WDK 10 (10.0.22621 или новее).
- Сертификат для подписи (на этапе разработки допускается Test-Signing).
- Возможность запускать системную службу от имени LocalSystem.

## Архитектура
```
+---------------------------+
| tickMeter.exe (WinForms) |
+-------------+-------------+
              |
              v
+---------------------------+          +------------------------+
| TickMeter.DriverBridge    |<-------->| WFP Callout Driver     |
| (Windows Service, C#)     |  IOCTL   | (KMDF, C++)            |
+-------------+-------------+          +------------------------+
              |
              v
+---------------------------+
| ConnectionTrackerCache    |
| (общий в памяти / IPC)    |
+---------------------------+
```

### Компоненты
1. **WFP Callout Driver**
   - Слой: `FWPM_LAYER_ALE_FLOW_ESTABLISHED_V4/V6` (по потокам) и при необходимости `FWPS_LAYER_OUTBOUND_TRANSPORT_V4` (по пакетам).
   - События: фиксируем PID, локальный/удалённый адрес и порт, идентификатор интерфейса, флаг туннеля.
   - Передача данных: создаём устройство `\\Device\\TickMeterWfp` и очередь IOCTL для записи событий в кольцевой буфер.

2. **DriverBridge Service (C#)**
   - Загружает драйвер при старте (`ServiceBase.OnStart`).
   - Читает записи через `DeviceIoControl`/`FILE_FLAG_OVERLAPPED`.
   - Поддерживает кэш: `ConcurrentDictionary<FlowKey, FlowMeta>` с TTL (например, 5 минут).
   - Экспортирует данные для `tickMeter.exe` через именованный канал (`NamedPipeServerStream`) или `MemoryMappedFile`.

3. **tickMeter.exe**
   - При старте пытается подключиться к `DriverBridge`. Если не удаётся, пишет варнинг и работает по старой схеме.
   - При обработке пакетов для Live View сначала проверяет кэш драйвера, затем ETW/IpHlpApi.

## Пошаговый план работ

### 1. Подготовка окружения
- Установить WDK и включить Test-Signing: `bcdedit /set testsigning on`.
- Создать решение `DriverSolution.sln` в каталоге `driver/` с проектами драйвера и сервиса.

### 2. Драйвер (C++/KMDF)
1. Создать проект "Empty WFP Callout Driver".
2. Добавить классы/функции:
   - `DriverEntry`, регистрация устройства и очередей.
   - Инициализация WFP (подписка на ALE Flow уведомления).
   - Handler `NotifyFn`, `FlowEstablishedFn`, `ClassifyFn`.
   - Структура `FLOW_EVENT` для передачи в юзер-режим.
3. Реализовать кольцевой буфер в пуле NonPaged + блокировку спинлоком.
4. Обработчики IOCTL:
   - `IOCTL_TM_GET_EVENT` — выдаёт следующую запись.
   - `IOCTL_TM_PING` — health-check.
5. Добавить INF-файл для установки и опционально установочный скрипт PowerShell.

### 3. Сервис (C#/.NET Framework 4.8)
1. Проект `DriverBridge` (Windows Service).
2. Логика:
   - `OnStart`: проверка подписанного драйвера (`sc create` + `StartService`).
   - Фоновый поток читает события через `DeviceIoControl` (пакетно,, размер буфера 4 KB).
   - Кэш в памяти (`ConcurrentDictionary`) + очистка по таймеру.
   - Общение с GUI: именованный канал `\\.\pipe\TickMeter.FlowCache` + сообщения JSON.
3. `OnStop`: останавливает драйвер (если сервис владеет жизненным циклом) и очищает ресурсы.

### 4. Интеграция в tickMeter
1. В `App.cs` при запуске подключаться к каналу.
2. В `ConnectionTracker`/`VpnBypassHelper` добавить `FlowCacheClient`:
   - Метод `TryGetProcess(flowKey, out meta)`.
   - При попадании обновлять `ConnectionEntry.ProcessName` и `ProcessId`.
3. Логирование: при недоступности кэша писать предупреждение и использовать fallback.

### 5. Тестирование
- **Возврат PID**: запустить браузер через VPN, убедиться, что события приходят с корректными PID.
- **Нагрузочное**: скачать файл/стрим, замерить влияние на производительность (
  target <5% CPU для сервиса).
- **Стабильность**: перезапуск драйвера, отключение службы, работа без драйвера.
- **Безопасность**: убедиться, что сервис обрабатывает ошибки IOCTL и не падает (try/catch + back-off).

### 6. Упаковка
- MSI/WiX bundle: устанавливает драйвер (INF + cat), службу, регистрирует автозапуск.
- Добавить переключатель в `settings.ini`: `vpn_driver_enabled=true` по умолчанию.
- В README/CHANGELOG описать новый компонент и требования к правам.

## Риски и смягчение
| Риск | План B |
|------|--------|
| Подпись драйвера недоступна | использовать только локally/test; предложить ETW-сервис как fallback |
| VPN блокирует WFP-слой | перейти на более низкий слой (NDIS) или комбинировать с ETW |
| Повышенные права нужны всегда | реализовать отдельный сервис, чтобы GUI оставался без UAC |
